# ModynToolbox Spec

2026-11-08 独立工具箱项目开发规格。根据用户已明确的架构、目录、启动和移交要求形成完整基线。

## 1. 目标与依据

面向个人在 Windows 本地反复使用脚本与小工具的场景。工具集中寻找、会话彼此独立，界面能留在主工作区、左右并排或放入独立窗口。以后增加工具时沿用主工作台能力。

### 已确认需求

- Windows 本地桌面软件。
- 产品名为 ModynToolbox，默认采用已获用户确认的浅色雾紫设计，一体化标题栏、左侧搜索、白色工作面板和克制的紫色强调。
- 搜索归工具导航。主区有用的标题保留。删除重复标签和底部会话列表。
- 工具可以并行使用。需要时独立成窗，日常使用不强制弹窗。
- 可持续扩充独立小工具。
- 主程序前台轻量、响应快、内存占用可控。
- 小工具界面可以遵循统一接入规范，后端语言和依赖独立。这是 2026-11-08 用户对接入方式的明确选择。

本文建议首批使用重命名、图片压缩、JSON 工具。主程序技术基线建议采用 C++20 / Qt 6 Widgets，工具后端通过进程协议接入，语言独立。该建议取代先前的全 Python 主程序建议。关闭独立窗默认收回，其他规则按已批准的开发基线实施。早期石墨深色方向由本轮已批准的浅色雾紫方案接替。

制定规格时只有交互参考。当前已实现原生试点与目录预览，实时进度见 STATUS。原浏览器草案只证明相应示意交互，Windows 验收按本规范执行。

## 2. 核心对象与交互原则

工具是功能种类。会话是一次独立使用。作业是一次实际执行。窗口是显示会话的位置。例如两份重命名会话分别处理照片和文档，参数、文件与结果互不覆盖。

一份会话最多有一个可见的编辑视图，未显示时保留模型和必要 UI 状态。分离/收回改变显示位置，不复制业务任务。会话可以多次提交作业，但同一会话默认只有一份非终态作业。

## 3. 功能需求

### F01 工具导航与发现

默认展开的左导航包含工具图标及完整名称，搜索入口常驻左侧，Ctrl+K 聚焦。工具增多时支持分类组织。空查询显示全部内置工具，按名称、分类及关键词搜索。无结果明确显示且不关闭当前会话。

点击工具优先恢复该工具最近活动会话，若在独立窗口则聚焦该窗口。未使用过的工具创建一份默认会话。搜索只定位工具，不执行文件操作。首版不设工具推荐大首页、营销展示、底部会话栏或收藏管理系统。

首次启动直接进入首个内置工具的空状态，后续启动恢复上次活动工具。空状态清楚提供添加输入的入口，用户可以立即开始工作。

### F02 多会话

工具标题操作区提供“新建会话”，默认创建空输入和该工具默认参数，不复制运行作业。与浏览器示意里复制参数的实现不同，正式版以本规范为准。

同类工具超过一份时才显示会话选择器。任务名可修改，默认使用“未命名 1”等可区分名称。有独立窗口的会话在选择器中标记。所有会话都可被再次找到，不能只列主窗口内会话。

### F03 主区与并排

默认主区显示一个会话，保留一个当前工具标题和简短任务名。工具内不重复同名标题，主区不再叠加一行同名标签。

“并排”允许选择另一会话，主区最多两栏。每栏保留自己的工具/任务标识及分离操作，总标题为“并排工作区”。不重复提供含义不清的全局分离按钮。窗口过窄时退为单栏切换，另一会话继续保留。返回单栏只隐藏另一个视图，不结束作业。

### F04 真正的独立窗口与收回

分离后获得可移动、缩放、在 Windows 任务栏/Alt+Tab 中识别的正常工具窗口。主窗口最小化后仍可单独使用。首版采用“一个会话一个窗口”，不做浮窗内多工具页签。

分离/收回保留输入、选项、文件勾选、结果、滚动和执行状态，作业 ID 不改变。已独立的会话不在主区同步显示第二份编辑器。

工具独立窗的关闭按钮默认执行收回，不终止任务，不重复确认。收回后在主区激活原会话。原主区会话仍保留。全部会话独立时，主区显示简短状态与当前工具收回入口，不再复制一份工具列表。

### F05 后台任务与状态

处理任务在独立工作进程执行，UI 不等待阻塞。业务后端的隔离边界默认是一份作业的进程树，各工具各自启动，UI 与工具后端通过消息通信。全局默认最多两个处理作业同时运行，长批处理最多一个，为短交互请求保留名额。图片并发最多一个。其余排队，可取消排队任务。工具注册的并发限制可更严格，资源充足时可通过明确设置调整批处理并发。

状态包括排队、执行中、正在取消、成功、失败、已取消、中断。是否已产生输出与是否部分完成必须另外说明。切换工具、分离窗口或隐藏视图不取消作业。同一会话运行时冻结该次输入，想处理另一批需新建会话。

处理进程异常只结束对应作业并展示可恢复的错误，不应连带终止其他正常作业。不宣称本地进程是对任意第三方代码的安全沙箱。

### F06 状态恢复

会话内切换始终保留编辑状态。跨启动默认恢复已开工具、任务名、普通参数、导航宽度、窗口位置和布局。不自动重新执行任务。

文件清单和粘贴文本默认只保留到本次应用生命周期。用户可选择保存特定会话草稿，保存前说明内容将存本地。未保存的内容在退出提示中说明。草稿恢复只加载草稿，不自动重新处理文件。恢复时文件缺失、屏幕移除或工具不可用，保留提示并降级到可见位置，不阻断启动。

异常退出前仍执行的作业标为“中断”。读取已有执行记录，但不自动重跑文件写入。大文本工作进程所需的临时输入允许暂存于应用目录，完成后清理。异常遗留在下次启动按本应用记录清理。

### F07 独立工具模块与扩充

工具以独立版本包提供名称、分类、关键词、图标、默认配置、界面描述、执行入口、运行环境声明、状态版本及取消能力。主工作台提供导航、原生组件、会话、窗口、任务及持久化服务。

支持现有组件的第四个工具通过增加兼容工具包接入，主程序无需重新编译。工具不直接访问其他工具模型或主程序数据库。需要新型复杂交互时扩展通用组件与界面规范版本，由宿主升级提供支持。

首版接入随包或用户明确导入的可信本地工具包，导入时检查兼容性与完整性。“原工具界面”采用同一规范界面在主区和独立窗复用。已有独立软件可后续通过适配器启动，任意第三方窗口内嵌另行评估。

### F08 批量重命名（推荐首批工具）

选择/拖入普通文件，默认不递归目录。提供前缀、后缀和可选序号（起始 1、位数 3）。首版始终保留最后一个扩展名，名称按“前缀 + 原主名 + 后缀 + 可选的 _序号 + 原扩展名”生成，例为 `旅行_照片_001.jpg`。列表可调序，序号按明确的列表顺序生成。

预览展示原名、新名和冲突。不修改文件。规则、勾选和排序改变后预览失效，重新生成有效预览才可执行。扩展名保持原样。不提供移动目录或修改文件内容。非法名称、缺失/被改变的源文件或不可访问目标阻止执行。目标重名时，仅允许目标正好属于同批已选源且可以统一迁移的交换/大小写变化，其余冲突阻止执行，禁止覆盖。

执行前展示受影响数量并确认一次。提交阶段不提供中途取消，界面明确说明。其他会话仍能操作。成功记录批次，提供最近一批“尝试撤销”。撤销须重新检查文件身份和目标冲突，不能承诺任意情况下均可回滚。失败尝试恢复已改名称。无法恢复时列出真实位置与人工处理步骤。

### F09 图片压缩（推荐首批工具）

支持静态 JPEG、PNG、WebP。先扫描文件及基本信息，再由用户选择输出目录，默认输出 WebP、质量 80，不改变尺寸。允许选择最长边限制，默认关闭。不放大原图。

保留原图。目标已有文件时生成不冲突名称，不覆盖。PNG 的质量滑块禁用并说明其使用无损压缩规则。修正 EXIF 方向。默认不携带原 EXIF。透明图转 JPEG 时明确使用白底。动图、多页图片及未支持格式说明原因并跳过。

逐文件报告成功、失败、跳过及输出位置。取消在文件之间生效，已完成输出保留。正在处理的大图可能需要等当前单文件处理结束。不能把部分完成说成完全未发生。

### F10 JSON 检查与格式化（推荐首批工具）

支持粘贴和载入 UTF-8 文件。显示错误行、列及简明原因，文本可复制、清空、格式化和导出。输入区域与结果区域角色清楚。错误不清空输入。

按严格 JSON 语法拒绝 NaN/Infinity。重复键给出警告且不静默合并。格式化只调整空白与缩进，保留键顺序、字符串内容和数字原始文字。不得通过浮点转换悄悄改变高精度数值。导出已有文件需要用户明确选择替换，不自动覆盖载入文件。

### F11 结果、任务详情与错误反馈

运行状态显示在所属工具操作区。全局只在存在非终态作业或未读失败时出现小型任务入口，点击打开详情。不恢复常驻底部会话列表。

详情包含工具、任务、阶段、进度、已完成/失败数、取消能力和输出位置。错误提供重试/修改参数/打开结果等适用动作。重试创建新作业，写文件作业不自动重试。结果能反向定位所属会话。

### F12 外观、键盘和最小设置

默认浅色雾紫主题。窗口标题与侧栏协调，白色工作面板、细边框、轻微静态渐变，主要操作使用紫色。系统外框集成拖动、缩放、最大化、系统菜单与吸附。设置只包括界面密度、字号/随系统缩放、草稿保留与任务/输出偏好。第一版不做主题商城、无限自定义或账户系统。

支持可见焦点、Tab 顺序、图标可访问名称、完整标签及错误文本。Ctrl+K 聚焦左侧搜索。Ctrl+Tab 在主区会话间切换。新会话和更多操作有可发现入口，不依赖快捷键才能使用。

### F13 文件资源冲突

不同会话的配置独立，不等于允许同时改同一文件。应用内对源/目标路径做读写预约，发生冲突时排队或明确提示。运行前再次验证实际文件状态。外部程序仍可能改动文件，检测到变化停止相关操作并记录，不作绝对并发安全承诺。

### F14 关闭、退出与清理

切换和收回不结束作业。用户显式结束会话时，如有非终态作业，提供留在应用、等待或取消该工具支持取消的作业，不能静默丢弃任务。

关闭主窗口意味着退出整个应用。没有运行任务且没有未保存临时内容时直接保存布局退出。否则一次对话说明所有相关影响。重命名提交关键阶段提供等待，不提供普通强制终止按钮。首版不做后台托盘常驻。不将“主窗关闭”解释为程序仍暗中运行。

### F15 本地分发

提供 Windows x64 文件夹式应用包，普通用户无需自行安装 Python。路径/输出对话框支持中文及空格。依赖与许可证随包记录。首版不包括自动更新服务、发布服务器或代码签名购买。

### F16 统一界面接入

工具描述所需参数、原生布局组件、动作和数据绑定，主程序验证后创建界面。首版覆盖参数表单、文件表格、文本输入/结果、图片预览及状态反馈。业务校验、扫描、预览与处理通过后端执行。没有打开的工具只保留登记信息，后端尚未执行时不启动其进程。

界面描述使用有界组件与简单条件规则，未知组件或不兼容规范版本给出明确提示。现有组件可组合出不同布局，工具名不作为主程序业务分支。

### F17 独立运行环境与数据

每工具声明精确运行环境及入口，版本被会话/作业固定。冲突的依赖版本使用不同环境。兼容工具可复用同一个不可变环境的磁盘文件，执行进程仍各自创建。后端使用独立的工作目录、配置、工具数据、作业临时文件和日志。用户电脑上的全局 Python/pip 不属于工具依赖来源。

宿主仅保存会话元信息、布局与作业索引。工具专用数据库归该工具管理。目录划分提供协作与故障隔离，运行权限遵循当前 Windows 用户权限，强权限隔离需额外操作系统机制。

### F18 受控通信与资源

消息具备协议版本、工具/会话/作业标识与输入修订号。错误格式、超长消息、异常退出、日志洪泛和过时结果局限到对应作业处理。大文件与结果通过有归属的文件引用传递。

宿主管理全局并发、工具并发与文件预约，并按工具配置管理工作进程资源预算和生命周期。一个后端崩溃后其他正常作业与界面仍可操作。CPU、物理内存、磁盘和 GPU 仍由同一台电脑共享，极端资源压力需通过限制和调度缓解。

### F19 独立版本安装与移除

导入包先校验，再启用新版本。运行中作业继续使用固定版本，既有会话保留其版本引用，新会话使用当前启用版本。当前被使用的包和环境不能卸载。卸载程序包默认保留工具数据，删除数据需要明确操作。旧数据迁移与恢复保留备份及版本提示。

### F20 界面故障边界

首版由一个宿主 UI 进程绘制主窗及各工具独立窗，后端各进程树独立。协议错误、后端崩溃和依赖冲突按工具隔离。宿主 UI 本身崩溃仍会影响全部宿主窗口，恢复由会话状态与作业日志完成。需要每份 UI 自身也强隔离时，后续单独评估额外 UI 进程及资源成本。

### F21 清晰项目与数据结构

项目在独立根目录从零开发。宿主模块集中 app，每工具在 tools/<tool_id> 集中业务核心、独立运行入口、适配层、界面、测试及依赖声明。共享协议/SDK 集中 shared，脚本集中 scripts，规划与记录集中 docs。

开发数据集中项目/data，生成物集中 .local。各工具数据集中 data/tools/<tool_id>，包括配置、专用存储、草稿、作业、日志和导出。工具原项目与安装副本分开管理。

### F22 开发与使用入口

提供 VS Code 可打开的根工作区。实施阶段提供 F5 构建/调试、无调试启动及同一 CLI 入口。首次运行检查兼容编译器、SDK、Qt、CMake 与所需后端环境，错误给出明确原因和处理入口。

PyCharm 可用于单个 Python 工具独立开发，工具核心保持编辑器无关。便携发布包有根目录启动程序，主程序依赖和工具分别集中。路径支持中文/空格，启动不依赖终端当前目录。

### F23 持续记录与开发交接

项目提供 AGENTS.md、README、当前状态、需求、架构、任务、验收、开发指南、决策、工作日志和验证证据。每个有意义阶段维护实际进度、相关变更、已执行验证、缺口和下一步。

源码和文档通过 Git 管理，本机路径、用户数据和生成物按规则排除。接手信息保存在项目文件内，别的开发者/Agent 可以按阅读顺序恢复上下文。自动读取能力不同的工具使用显式交接提示。

### F24 跨电脑迁移

源码迁移携带工程、锁定依赖和记录，新机器按诊断重建工具链和缓存。便携程序正常退出后可携带整包及数据迁移，目标电脑需满足运行前提。外部文件缺失时可重定位并复验。

开发默认项目/data，便携版默认包内/data，支持显式数据根。不可写时提示选择可写位置，同一数据根保持实例互斥。提供一致性数据导出/导入，预检版本和完整性、备份当前数据、失败保留原内容，写入任务不会自动重放。

## 5. 版本范围

首版包括雾紫外观、导航/搜索、单区/并排、同类多会话、真实独立窗口与收回、基础恢复、任务管理、统一界面接入、独立工具包/环境/数据、三个推荐工具和 Windows 包。

后续候选包括收藏/更多分类、用户配置模板、更多工具、逐个适配已有 EXE、经过需求验证的快捷启动。在线插件、云同步、工作流编排、多工作区管理、移动/Web 版不进入首版。

工具接入接口只覆盖首批真实界面所需能力，随新工具迭代通用组件与协议。

## 6. 重要假设与待审阅选择

- **A01** 首批三个工具用于验证三类交互，用户可替换。平台与窗口基础不随工具清单改变。
- **A02** C++20 / Qt 6 Widgets 为本次工程建议，用户已确认界面接入规范与后端独立要求。精确依赖组合与性能数据待 M0，用户尚未逐项选择具体版本或资源预算。
- **A03** 独立窗 × 默认收回，主窗 × 退出。这是建议的产品语义，编码前应一并审阅。
- **A04** 默认不跨启动恢复原始文本/文件清单，允许保存草稿。应用生命周期内必须保留状态。
- **A05** 不实现任意已有 EXE 的无缝内嵌。现成工具接入要逐个分析。
- **A06** 目标是个人可信工具集合。进程分离用于响应和故障隔离，不是恶意插件防护平台。

## 本轮实施授权与目录移除语义

2026-11-08 用户明确要求最后核对方案并按开发阶段实施，后续按任务依赖连续推进。

已安装工具包目录为可核验的程序来源。宿主启动与刷新时核对目录，缺失包撤下入口并保留数据/历史，相关保存会话显示缺失。文件夹手动移除以正常退出后进行。运行中通过应用移除入口协调等待/取消，检测到部分缺失时停止新提交并记录实际错误。源码工具目录与安装副本分别管理。

目录索引可从有效包重新生成，缓存不决定已删除包仍可执行。共享环境按仍存在的引用核算，未解决 journal 与用户数据不自动删除。需要补充目录缺失、部分删除和重新放回包的回归验证。

## R2 全量交付授权

用户要求先整体核对优化剩余方案，再一次完成所有剩余实现，由用户做最后完整检查。此授权覆盖既定 T01–T12、真实三工具、发布、数据/版本迁移、全量自动验收及新增第四工具的接入实测。内部仍按依赖实施并持续记录，不逐阶段请求重复确认。
