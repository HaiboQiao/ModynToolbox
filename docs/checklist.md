# ModynToolbox Checklist

2026-11-08 按原生宿主与独立工具架构修订。当前完整产品验收尚未完成，阶段子集证据见 verification。文档核对另见 validation.md。

依据为[spec](spec.md)、[plan](plan.md)、[task](task.md)。批准验收设计不等于执行通过。

## 环境和记录方式

首版必需环境包括真实 Windows 11 x64 普通账户。原生 GUI 与文件对话框。1920×1080 主屏 100%/125%/150%。双屏不同 DPI。干净、无 Python 的离线测试账户或机器。可创建/占用/变更测试文件的隔离目录。

当前已有原生试点、开发依赖与部分自动化证据，完整冻结发布包待实施。若双屏、干净机器等不可用，相关必需项保持未验证，不以浏览器截图或单屏仿真替代。Windows 10、ARM64、移动/Web、第三方 EXE 内嵌不属于本次通过范围。

每项证据记录系统、显示缩放、应用/依赖版本、输入、动作、观察、结果及截图/测试输出位置。自动测试统计需含用例数及跳过原因。未收集/全跳过不是通过。下列测试入口由任务逐项建立，尚未创建的入口保持待验。

## 行为与界面

- [ ] **C01（AC01）必需 / 原生 GUI。** 搜索位于左导航，输入三种工具名称及无匹配词。观察正确定位/空结果，主区仍保留当前输入。检查只有一层主区标题，无底部会话列表和同名页签。验证入口为 T03 的 GUI 场景与 `app/tests/unit/test_navigation.cpp`。
- [ ] **C02（AC01,AC14）必需 / 原生 GUI。** 用键盘 Tab/Ctrl+K 搜索并进入工具。焦点可见且不被面板挡住，所有图标动作可识别。截图包含默认、Hover/Focus、Disabled 和错误状态。不据此宣称完整屏幕阅读器合规。
- [ ] **C03（AC02）必需 / 模型+GUI。** 新建两份重命名会话，分别选不同文件/前缀/勾选。多次切换后互不覆盖。第三份会话空输入，不继承作业。只有多实例时出现会话选择器。验证入口为 `app/tests/unit/test_sessions.cpp` 与真实输入。
- [ ] **C04（AC03）必需 / GUI。** 重命名与 JSON 并排。主区有总标题与各栏标识，分离动作各归其栏。缩小退单栏后另一会话及任务仍可找回。并排关闭不删除模型。
- [ ] **C05（AC04）必需 / Windows。** 在有文本、选项、勾选、滚动和结果的会话中分离→编辑→收回，所有状态正确，session_id/job_id 不变，没有重复提交。验证入口为 `app/tests/unit/test_window_lifecycle.cpp` 与真实窗口。
- [ ] **C06（AC04）必需 / Windows 外壳。** 独立窗可移动/缩放，任务栏和 Alt+Tab 可识别。主窗最小化后仍可操作。独立窗 × 收回而非结束任务。把所有会话分离后，仍能从导航/选择器定位并收回。同类浮动和主区实例可分别找到。
- [ ] **C07（AC05,AC11）必需 / 真 worker。** 启动耗时批处理与一份模拟交互任务时切工具、搜索、移动/收回窗口。界面可交互、进度归正确会话。第三个交互任务排队，两个批处理不同时执行，短交互可使用保留名额。运行时重复点击不会提交两份活动作业。
- [ ] **C08（AC05）必需 / 文件与 worker。** 图片读取某文件时提交对该文件的重命名，观察资源冲突排队/提示。释放资源后再执行，最终文件状态与作业记录一致。外部替换源文件时复验失败，不用覆盖强行继续。
- [ ] **C09（AC11）必需 / 协议与故障。** 正常消息分成半行/UTF-8 片段或多行读取时正确重组。worker 崩溃、退出无终态、EOF 残缺、坏行/超长消息得到明确失败，过时事件不覆盖新状态。其他正常作业继续，重试生成新 ID。验证入口为 T05 的协议与崩溃测试。

## 恢复、退出与数据

- [ ] **C10（AC06）必需 / 重启。** 一会话明确保存草稿，另一会话不保存正文/文件清单。重启后仅按策略恢复。恢复任务不自动执行。缺文件/缺工具给提示，不导致启动失败。
- [ ] **C11（AC06,AC14）必需 / 双屏。** 将独立窗移到不同 DPI 屏幕，再改变缩放、移除副屏并重启。窗口落在可见工作区，正文/主要动作可读且不裁切。
- [ ] **C12（AC12）必需 / 原生退出。** 无运行任务/未保存内容时直接退出。有运行/未保存内容时只出现一次汇总处理。图片可请求取消并退出，重命名提交阶段只等待。独立窗关闭不触发应用退出流程。
- [ ] **C13（AC06,AC12,AC15）必需 / 受控崩溃。** 只结束测试创建的父应用，核对所属 worker 不残留继续写入。重启标记中断，保留 journal/已输出内容，无自动重跑。检查陌生进程和用户无关文件没有被结束/删除。
- [ ] **C14（AC15）必需 / 数据目录。** 定位当前明确的数据根、各工具草稿/作业/日志。正常完成清理临时输入，异常遗留按记录处理。保存草稿前的默认策略与提示一致。日志无粘贴正文，用户目录输出不随会话清理删除。
- [ ] **C15（AC06,AC15）必需 / 数据迁移。** 使用旧版、损坏和更高版本状态库，观察备份/错误/只读提示，旧库不被静默清空。历史裁剪不删除待恢复 journal。

## 三个推荐工具

- [ ] **C16（AC08）必需 / 隔离普通文件。** 导入带 Unicode/空格的文件，按序号/前后缀预览。执行前原文件名及字节不变，冲突/非法名/目录项明确阻止。取消确认不产生文件变化。
- [ ] **C17（AC08）必需 / 文件。** 执行正常改名、交换名称和大小写变更。名称与已确认计划一致，内容哈希相同。目标被外部抢先创建时不覆盖。成功清单与磁盘逐项对应。
- [ ] **C18（AC08,AC12）必需 / 故障恢复。** 两阶段移动中分别注入权限/占用/中断。核对 journal 和部分恢复清单。撤销前替换或改动目标文件，撤销拒绝冲突而不覆盖。不能只看“撤销按钮存在”。
- [ ] **C19（AC09）必需 / 自制图片。** JPEG/PNG/WebP、EXIF 旋转、透明图转 JPEG、PNG 无损选项逐项验证。输出可解码、方向/尺寸/底色符合规则，原图哈希不变。重名输出不覆盖。坏图/动图逐项报告。
- [ ] **C20（AC09,AC11）必需 / 真图片批次。** 处理多张图片后请求取消，当前文件完成后停止下一张。已发布输出数量/路径与详情一致，临时文件按记录清理，源图未变。编码异常与部分成功计数正确。
- [ ] **C21（AC10）必需 / JSON。** 输入缺引号、逗号、深层嵌套、BOM、错误编码，检查行列及输入保留。NaN/Infinity 拒绝，重复键警告。检查结果与大文本 worker 实际调用一致。
- [ ] **C22（AC10）必需 / JSON 精度。** 格式化包含大整数、精细小数、指数、转义及重复键的输入，比较非空白 token 与原文一致。复制/导出成功结果，载入源文件不被自动覆盖。
- [ ] **C23（AC16）必需 / 容量边界。** 重命名恰好 2000/超过 2000 文件，图片恰好 500/超过 500 文件、50 MiB 和 4000 万像素边界，JSON 恰好 5 MiB/多 1 字节。单位按 spec。对应预检明确接受/拒绝，没有截断后执行，UI 不卡死。

## 扩展、发布与完整路径

- [ ] **C24（AC07,AC17）必需 / 已构建宿主。** 保持宿主二进制不变，导入第四兼容工具包，走主导航→创建会话→执行→独立窗→收回→结果。检查没有工具专用分支，测试包不进入正式发布包。验证入口为 T12 的 extension_install。
- [ ] **C25（AC13）必需 / 干净 Windows。** 普通账户、断网、无 Python 运行文件夹包。所有正式工具、图标、Qt 文件对话框及编解码可用，worker 不弹 GUI/控制台，中文/空格路径工作。
- [ ] **C26（AC14）必需 / 真实图形环境。** 在规定 DPI 与窗口尺寸下对照雾紫方向拍主区/并排/独立窗/错误/空态截图，检查文本换行、表格、焦点和主要操作。记录系统标题栏/对话框差异，浏览器截图不替代此项。
- [ ] **C27（AC01–AC05,AC08–AC12）必需 / 端到端。** 打开工具台→重命名预览资料→新建另一任务→图片批处理→分离图片窗→JSON 检查→取消图片→收回→确认执行改名→检查真实文件→正常退出/重启。核对每次输入、作业、窗口及实际输出归属，其他任务没有被覆盖。
- [ ] **C28（AC05,AC13,N03）必需 / 工程记录。** 执行 T12 全部测试并记录数量/跳过/失败。记录参考机器、冷启动、空载/处理内存及交互观察。没有证据时不填写保证值，不以测试汇总替代逐项业务验收。

## 独立工具架构

- [ ] **C29（AC17）必需 / 组件。** 用兼容 UI 描述创建表格/表单与文本布局，未知组件、错误字段/动作引用、超深树/超限节点只显示该工具错误面板。检查后端不在 UI 进程导入。入口为 T02/T03 的 view_spec 与 catalog。
- [ ] **C30（AC18）必需 / 两种语言。** 宿主同时启动 Python 与编译型 worker，执行、取消、返回文件引用结果。使一方崩溃，另一方输出和会话保持正确。两份同工具任务分别使用不同输入。入口为 T01/T05 的 workers。
- [ ] **C31（AC18,AC19）必需 / 两环境。** 构建相同测试依赖名、不同实现/版本的两个独立环境，实际导入返回各自结果。修改一方测试配置只影响该工具目录。用户全局 Python/PATH 不改变实际选择的入口与依赖。入口为 T05。
- [ ] **C32（AC18,AC20）必需 / 进程树。** worker 在初始化及执行阶段分别派生子进程，确认在执行外部工具代码前已纳入所属作业组。注入归属失败不执行业务。结束一作业进程树和受控父宿主崩溃时核对其他应用不受影响。入口为 process_tree。
- [ ] **C33（AC19）必需 / 包版本。** 旧版运行时导入新版，新会话用新版本，旧会话/作业仍固定旧版。损坏包启用失败保留旧版，忙碌/被引用包拒绝卸载。默认移除代码保留数据，共享环境引用未清空时不能删除。入口为 package_install 与 extension_install。另在退出后手动删除运行工具包，启动/刷新应撤下缺失入口并保留历史数据；部分缺失应报告，重新放回兼容包可恢复发现。
- [ ] **C34（AC20）必需 / 负载与测量。** 100 个仅登记工具、20 份 parked 会话、1/5 个显示窗口、2000 行表格、两异语言作业及连续 50 次开关。报告冷/热启动、空闲 CPU、宿主和完整进程树的专用内存/工作集、处理峰值、缓存与内存趋势。负载数量属于测试样本，资源预算以 M0 明确基线判断。
- [ ] **C35（AC20）必需 / 洪泛与限额。** 发送超长 JSON/海量进度/诊断、过时修订结果、超限引用，观察有界缓冲与进度合并，错误局限到作业。对独立测试 worker 验证资源上限触发、取消政策及部分副作用记录。工具持续占用磁盘/GPU时检查并发策略与 UI 响应，不能据此宣称物理资源完全隔离。
- [ ] **C36（AC19,AC20）必需 / 数据与故障域。** 分别定位 host DB、各工具数据/日志与作业目录。改变工具私有数据不修改其他工具。实测并记录宿主 UI 被终止时所有宿主窗关闭及按策略恢复。可信工具当前用户权限仍可访问其系统允许的路径，目录划分不计作权限沙箱。
