# 架构与工程决策记录

2026-11-08 建立。以下为本项目开发基线，具体依赖版本和资源预算在 M0 落实。改变决定时追加新的记录并链接受影响需求与验证。

## D001 原生宿主与独立后端

C++20 / Qt 6 Widgets 宿主管理 UI、会话与调度，后端通过独立进程协议接入。依据为前台轻量、统一界面和混合语言要求。代价为 C++ 工程维护，性能仍需发布包实测。影响 spec F05/F16–F20 和 plan §1–7。

## D002 工具核心、适配和界面分开

tools/<id> 内集中 core、standalone、integration/adapter、integration/ui.json 和 tests。核心可单独运行和测试，适配层处理协议，界面围绕实际任务设计。现有组件可表达的工具单独发包，全新 UI 组件涉及宿主升级。

## D003 源码、数据和生成物分别集中

app、tools、shared 保存可维护源码。data 保存运行内容，.local 保存机器环境和构建派生物。宿主测试在 app/tests，各工具测试在自己的 tests。锁定文件与恢复说明进入 Git，机器路径及数据按忽略规则管理。

## D004 便携数据根优先

按照用户希望目录集中、便于迁移的要求，开发默认项目/data，便携发布默认发布目录/data，支持显式 --data-root。根不可写时提示选择，不静默转存到其他目录。每工具的数据集中 data/tools/<id>。此决定取代早期讨论的默认 AppLocalData 方案。代价为共享/只读位置需要明确数据根，同一数据根使用实例锁。

## D005 开发与发布入口

开发默认 VS Code，统一 CMake Preset 和 scripts/dev.ps1，M0 实现 F5 与 CLI 一致的入口。PyCharm 用于独立 Python 工具开发。发布以便携目录为首版，根目录轻量启动器调用 app 内主程序，Qt DLL 与插件集中 app。需要额外维护轻量启动器及其错误反馈。

## D006 稳定协议与本地工具包

清单、界面、消息各自版本化，stdio JSON Lines 传控制与进度，大数据走有归属文件引用。工具包按版本启用，会话/作业固定版本。初期可信本地包，独立进程和私有目录提供故障/协作隔离，权限仍由 Windows 决定。

## D007 自包含交接记录

AGENTS、README、STATUS、四份规划、development、decisions、worklog 和验证报告形成文件内上下文。Git 维护源码历史。不同 Agent 自动读取能力有差别，handoff 提供显式提示。当前交付不要求个人全局 Skill、旧聊天或旧项目目录。

## D008 验证优先的阶段推进

M0 验证环境、启动、窗口、异语言与进程树、性能和最小发布包，M1 实现工作台，M2 完成真实工具，M3 做迁移与发布验收。数字预算以参考机器实测制定，当前未给出未经测量的启动/内存承诺。

## D009 工具导航与非打扰验证

用户指出任务命名、白色外框和桌面控制问题。导航展示工具，会话选择器仅在同工具多实例时出现。先应用原生 DWM 深色标题栏保留系统窗口操作，API 不支持时使用系统默认行为。独立 windows-check 与 offscreen 是默认验证路径，避免抢占前台。真实系统交互保留单独验收。

## D010 目录发现先行

用户要求继续下一阶段，因此在 T01 未完成时先开发 T02 不依赖执行器的元数据发现子集。源工具与安装副本分开，正常启动只扫描安装副本。显式 prepare-preview 可以补回示例清单，普通 run 不补包。预览清单不是可执行业务包，完整安装与版本引用语义仍按原方案开发。

## D011 ModynToolbox 与雾紫主题

用户明确批准新设计并要求全项目与目录更名。有效项目根、工作区、CMake 目标、可执行文件、环境变量、文档与 UI 使用新名称。旧名称仅存在不可变 Git 历史及生成历史记录中。产品默认雾紫浅色主题，统一标题区域、控件与图标。早期深色方案保留为历史证据，新的视觉约束以 plan §11 为准。

## D012 共用窗口与有界界面预览

ChromeWindow 供主窗和工具窗复用。Windows 保留 native frame 样式并集中处理命中与状态，DWM 请求圆角与边框。离屏与隐藏句柄测试各验证自己的范围，真实吸附、阴影、DPI/多屏独立验收。

先提供 text/files 与少量参数类型的有界预览，单工具界面集中在 integration/ui.json，宿主按布局能力渲染。清单图标独立于 UI 文件，导航不预读所有界面。旧清单可以回退，声明界面的包缺文件必须报局部错误。业务处理入口在受控后端通路接入后启用。

## D013 正式跨语言工具接入与完整交付

R2 以有界 v1 清单、UI、JSONL 控制和结果文件接入四个真实工具。工具自身构建并携带运行时，主程序只按声明渲染，源码/二进制冻结后实测接入。共享 SDK 仅承担协议。包版本固定且同版本内容不可覆盖。主界面、独立窗口、并排与后台作业按稳定会话 ID 归属。

## D014 资源与数据收尾

Windows JobObject 在工具代码启动前绑定可信桥，限制内存、进程和 CPU。预检与执行分离，默认两槽/一重批，同工具串行，设置可调整重批上限。宿主导出复用同一调度与文件预约，临时写完后原子提交。

SQLite 保存元信息、可选草稿及有限摘要。拒绝加载的数据库不允许保存，无法恢复显示的草稿保留。备份采用一致性 SQLite 快照、索引校验、暂存和迁移日志，保留旧数据。

## D015 大文本预览预算

实测大文本直接交给 Qt 排版造成明显 CPU 和内存开销。采用 32768 个 UTF-16 码元的只读显示预览，完整数据继续用于处理、复制与导出。5 MiB 输入回归验证完整性。JSON 格式化正则避免逐字符回溯状态膨胀。该决定属于首版实现取舍，已写入用户说明。

## D016 验证与真实设备边界

默认以 offscreen、隐藏 HWND 和自有进程/数据根验证，保护用户桌面工作。多屏 DPI、Snap、系统对话框和另一台干净电脑保留最终人工检查。冻结接入实验中的公共 UI 改进单独记录，改进后重新冻结并复验，不把开发全过程宣称为宿主从未修改。

## D017 左侧会话树与纯工具工作区

UI-R3 将公共会话操作统一迁到导航。单会话紧凑，多会话展开，展开状态进入既有状态 JSON。ToolNavigation 只持稳定标识并发出操作意图，Workbench 保有模型、后台作业和窗口归属。拖动超过系统距离且在主窗外释放才分离，静止按住、窗口内释放与 Esc 保持原位置。主窗品牌两行，浮窗第二行显示具体工具和会话，中央只显示工具内容。用户明确要求小型优化修改直接实施，规划请求则清楚说明交付阶段。
