# UIR-7 五项窗口/工具交互优化

2026-11-15完成本地优化。宿主1.4.0、内置五工具1.2.3；保留1.2.2及已有数据/未提交改动，未发布、未上传GitHub。规格见[实施方案](../features/ui-r7-interaction/spec.md)。

## 原因与实际改动

1. 自绘无框窗口虽然已有THICKFRAME和边缘命中，但原代码没有明确转交边缘按下的原生缩放处理，显示时还可能被Qt更新窗口样式；嵌入的WebView原生子窗口也不能覆盖缩放边缘。ChromeWindow显示后恢复原生样式、保留8逻辑px功能边缘（最大化/全屏0）；八向非客户区按下交给DefWindowProcW，保留标题拖动、最大化、关闭和浮窗收回。不能凭这组自动化断言旧版用户现场的唯一触发原因，物理拖动仍单列设备验收。
2. parkUnused旧实现切走立即请求检查点并销毁所有非活动页。原生基线三次返回JSON等待6692/6380/6383ms，页面身份标记每次消失。改为最近两个闲置Web页面保温60秒，超额LRU/超时回收；初次懒加载、包校验不变，忙碌/并排/独立页保护、检查点失败不丢页面。热切换以多保留少量页面换取速度，不承诺内存不增加，也不保证首次/回收后的冷启动同样快。保护页面可能暂时超过两页额度。
3. 各工具自有base.css原为1px边框再加2px外圈/2px偏移；改为输入/选择的焦点只变1px边框颜色。按钮、复选框和范围控件仍保留细键盘焦点线。公共Qt控件已有1px焦点边框，保留。
4. 去掉宿主工作区24px四周留白，工具自己的20px内容内距改为12px（窄屏10px）；浮窗不再额外套旧控件20px边距。右区由工具完整视口占据，功能缩放边缘仍保留。
5. UiSpinBox/UiComboBox忽略滚轮；五工具各自interactions.js在数字/范围/选择上取消默认滚轮改值，把滚动交给最近可滚动祖先/页面，保留焦点、键盘和点击操作。Ctrl+滚轮保持浏览器缩放手势约定；普通滚轮不会改值。SDK和宿主不注入CSS/业务JS。

## 验证中纠正的问题

第一次完整检查16/17通过，Web新增断言中两个问题已纠正：panel()访问器会懒创建页面，不能用它验证已卸载，改为QPointer销毁证据；本机150%DPI下1px CSS边框的计算值可为0.666667px，且非激活窗口无法真实获得OS焦点。现在按真实规则强制**仅测试文档**焦点伪状态并检查细线渲染/颜色，生产没有注入；滚轮验证仍操作真实工具控件。随后Web专项8/8及最终完整17/17通过。切换计时辅助脚本首次误将typeof结果与标记值比较，修正辅助断言后同条件三轮通过；旧失败日志仍保留，没有以旧绿覆盖新失败。

WebView关闭异步清理造成部分QTemporaryDir残留警告，均在测试私有.local目录，未按进程名清理用户应用，也未修改用户工作区数据。

## 打开与设备边界

本地Open-ModynToolbox.cmd入口已指向`.local/releases/ModynToolbox-1.4.0-d58cc56a`；本地包data保持空、验证在私有副本中进行。Run-Dev.cmd/dev.ps1 run使用源码和开发data，旧会话仍锁定旧包；工具名右侧+可新建1.2.3会话，不自动迁移/删除旧输入。

验证全程不激活前台、不发送用户鼠标键盘事件。实际鼠标拖拽手感、Windows Snap、多屏物理DPI、IME及另一台电脑尚未冒充自动通过。当前模拟命中和系统缩放代码已验证，但不能代替用户设备上真实拖动。
