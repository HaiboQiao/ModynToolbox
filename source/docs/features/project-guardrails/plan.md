## 变更保护实现

标准库scripts/change-guard.py：validate检查现行文档入口/契约ID/真实测试名称与引用；start记录Git中已跟踪及未忽略新文件哈希（无Git时安全目录扫描）；review按实际改动检查允许范围、风险和保护项；verify运行固定的标准库自测与所需CTest，不执行记录中的任意shell命令；finish要求范围正确、必要复核说明和与当前代码内容绑定的真实验证结果。

快照同时保存开始时规则索引，原保护路径和测试路由不因本轮改配置而静默消失；bookkeeping只能作用于文档。快照记录开始时工作树，而不是仅与HEAD比较，不把IF-1/DS-1旧未提交成果算作本轮。所有输出在.local/change-guard，拒绝覆盖已有任务基线。删除同样比较；测试/规则变动提升复核要求，不自动允许变弱。检查不自动回滚、删文件、发版或改用户Git配置。

风险按代码位置保守路由，排期P0-P3不影响保护强度；无法分类的运行代码按高风险并扩大回归，不能静默当低风险。verify先构建当前源码并核对CMake缓存源目录，将结果绑定代码及构建产物摘要；确认CTest确实收集预期名称，避免零测试也通过；改代码、SDK、脚本、测试或核心基线后旧收据失效。状态/日志更新不使业务测试反复作废，finish仍实时执行文档一致性检查。

CTest加入change_guard，dev.ps1的test/package在构建前validate；不阻止用户普通打开/run，也不自动发布。新增独立工具的冻结实验提供可跟随源码使用的冻结入口，避免依赖本机.local手工脚本。

## 执行与风险

先留本轮内容快照；写规则/路由；实现护栏和负向测试；接入现有验证；执行当前任务自身的范围检查；归档报告。自举时说明快照先于新工具，不能伪称早已执行过不存在的脚本。

保护不是权限沙箱：AI可绕过脚本或编造说明；脚本不能理解全部业务意图或核验聊天授权真伪。仍须实际用户授权、审查和业务测试；不同AI是否自动读AGENTS不一致，所以提供显式交接。真实跨Agent/异机与物理设备验收不冒充本机检查。
