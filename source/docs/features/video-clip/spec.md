# 视频裁剪需求基线

2026-11-11，VID-1。状态为已按用户后续指令实现本地初版，当前验证和缺口见task/checklist及验证报告。用户本轮要求详细分析整体需求与初版方案，该条记录原规划阶段范围，后续用户已明确授权实现。当前公开版仍为 1.1.0。

## 目标与场景

为 ModynToolbox 增加独立的视频裁剪工具，tool_id 建议为 video-clip。输入一个本地视频，选取连续时间段，按需压缩并另存。服务于去掉片头片尾、保存其中一段、将整段或选段缩小以便存储或发送。全部本地离线完成。

每个会话处理一个源视频、一个连续区间、一次输出一个文件。不同视频用现有加号创建会话，沿用拖出独立窗口及关闭收回行为。首版先覆盖这些明确场景，暂不包含多轨、拼接、多段批量导出、删除中间片段后重组、字幕制作、特效、配乐、在线素材、AI 功能、按目标 MB 两遍编码及硬件编码。

## 已核实的项目基础

- C++20 / Qt 6.8.3 Widgets 宿主，四个独立业务工具，共用 Theme、UiSpinBox、UiComboBox。
- ui_schema_version / view_version 目前只支持 1，叶组件包括 files/text/fields/actions/output_text/output_table/image_preview/status，没有视频播放与时间选段。
- 现有 CMake 没有链接 Qt Multimedia。采用原生视频预览需要增加模块与部署文件。
- 当前任何 inputChanged 都清空 context。视频源元信息和导出参数需要分开失效，不能通过修改现有全局规则破坏重命名计划等工具。
- 每作业进程组内存上限最多 2048 MiB，动作总超时最多 3600 秒。长视频编码可能超过该时限，需按新版通用能力设计，不能承诺任意 4K 素材都可处理。

以上是当前实现事实。以下为本轮实现基线，真实验收和保留项以checklist为准。

## 用户能力与默认行为

| ID | 能力 | 初版行为 |
|---|---|---|
| F01 | 导入与检查 | 拖入或选择一个本地普通视频文件，自动异步分析时长、画面尺寸、旋转、帧率/可变帧率、文件大小、视频/音频流及可用操作。加入第二个视频时提示替换，已有未保存选段不静默丢弃 |
| F02 | 预览与定位 | 播放/暂停、静音/音量、进度定位、当前时间和总时长。选段可循环预览。切换离开会话暂停，返回不自动播放。浮窗移动同一页面不重开媒体 |
| F03 | 选择区间 | 默认整段，时间轴左右手柄、起止时间输入和“设为起点/设为终点”同步。显示选段时长和重置整段。有效约束为 0 <= start < end <= duration |
| F04 | 精确裁剪 | 默认导出方式，重新编码所选画面与音频，使用源时间戳定义区间。目标为首个不早于起点的画面，保留起止区间内的画面；时间显示到毫秒不代表素材拥有毫秒级帧精度 |
| F05 | 快速截取 | 单独模式，复制受支持的编码数据。先定位可独立解码关键帧，再展示调整后的区间。用户确认调整区间后导出，不静默扩大。禁用压缩/缩放等需要重新编码的参数，容器/编码不匹配时明确拒绝并引导精确模式 |
| F06 | 可选压缩 | 精确模式提供较高画质/均衡/较小文件三档，原尺寸/最长边不超过 1920/最长边不超过 1280 三档。默认较高画质、原尺寸、不放大、保留原始方向与比例；需要减小体积时再选均衡或较小文件。默认保留一个明确选定的音轨，可选择移除音频 |
| F07 | 安全另存 | 精确模式默认 MP4、H.264 视频、AAC 音频。默认源目录的 ModynToolbox Exports 子目录，可更改输出目录与基础文件名。同名自动编号，禁止覆盖源文件及已有文件。工具默认导出目录保留为用户可主动选择的备选 |
| F08 | 过程与结果 | 阶段、进度、已用时间、取消。分析阶段用不定进度，编码进度由媒体处理时间计算，最终校验前不显示完成。结果显示输出路径、时长、实际大小、相对原文件大小变化及打开文件/目录入口 |
| F09 | 独立会话 | 视频路径、区间、参数及结果归属各自会话。沿用宿主可选草稿策略，恢复前重新核对源文件，后台不自动继续播放或重新导出 |
| F10 | 接入与分发 | 业务、FFmpeg/ffprobe、适配和依赖集中独立工具包。新增公共视频组件完成后，此工具安装/移除仍遵循目录与刷新规则。旧版 1.1.0 无视频组件，不能直接加载完整交互版本 |

## 重要语义

- “缩短”减少保留内容；“压缩”通过重新编码/缩放影响体积与画质，两者可以组合。
- 快速截取保持所复制音视频流的编码质量，容器、元数据和文件字节会变化。不能称为任意时间精确无损裁剪。
- 精确模式会重新编码。即便保持分辨率，也不能承诺画质无损。
- 三档质量不承诺固定压缩百分比，也不承诺输出一定小于源文件。估算不是精确目标大小；第一版默认不展示缺少可信依据的精确体积预测。
- 快速模式只覆盖已验证且可复制的 H.264/AAC 等组合。特殊编码/容器走能力检测，不能只凭扩展名认定兼容。
- 初版保证范围以测试矩阵为准，优先 Windows 常见 MP4/MOV/MKV 中的 SDR 8-bit 视频，H.264 为主。HEVC 等能力由锁定的解码器实际验证决定。HDR、10-bit、交错、多音轨保留、嵌入字幕/附件/章节的完整继承暂不承诺，导出前明确提示被省略的内容，避免颜色或内容静默改变。
- 无音轨视频正常导出。多音轨先明确选择一个默认/首条音轨，并提示其他音轨不包含在输出。旋转、可变帧率与非零源时间起点必须正确归一化。
- 预览不支持而 ffprobe/编码支持时，保留时间输入导出路径并明确提示“无法预览”；不伪装成已验证的可视化选段。加密/损坏/无有效时长素材停止导出并给出原因。
- 一个输出只在编码退出成功、输出元信息校验通过并安全发布后算成功。编码结束、封装结束、文件发布是不同阶段。

## 失败、取消与安全

源视频以只读方式访问。最终导出前再次验证源文件身份、大小和修改时间；同一路径内容变化则要求重新分析。身份/大小/时间并不构成完整内容哈希，不能宣称可检测所有外部修改。导出期间若发现变化，拒绝发布结果。

输出目录创建失败或无写权限时要求重新选择目录。输出同目录使用不可冲突的私有暂存文件，完整结束后以禁止替换现有文件的提交方式发布。进程崩溃、空间不足、校验失败均不发布为成功文件。取消向适配器发送协议消息，停止 FFmpeg 并等待退出，超时由宿主管理对应进程树。已经提交成功的文件保留并按成功事实报告。

启动时清理只限本工具可验证归属的残留暂存文件，不删除用户文件。取消不承诺编码断点续传。并发会话使用不同作业目录和临时路径，相同目标名在最终提交时再次排重，预约不能替代实际文件提交检查。

首版是可信本地工具模式，独立进程是故障与依赖隔离，不是权限沙箱。使用 Qt Multimedia 的预览属于宿主公共 UI 故障域，媒体解码不具备独立进程隔离。

## 界面方案

沿用 docs/ui-design-system.md 的浅色雾紫、字体、密度、按钮和焦点状态。左侧公共工具/会话树不增加业务参数。中央只呈现视频工具内容。

空状态显示简短导入区。导入后顶部为文件名与元信息，主区左侧为视频，右侧为导出方式/质量/尺寸/音频/输出位置，预览下为时间轴和起止时间。底部一条状态与主要“导出视频”动作，运行时提供取消，完成后提供打开结果。高密度信息放折叠的媒体详情和高级项，不重复显示工具导航。

窄浮窗按预览、区间、导出设置顺序纵向排列，保持操作可达。预览画面允许深色承载区，外围仍沿用雾紫，紫色仅用于选段和主动作。手柄既能拖动也能键盘调节，时间输入可直接录入并有明确单位，避免空白步进按钮。

快捷键仅在视频控件拥有合适焦点时生效，文本输入时不拦截字符。空格播放/暂停，I/O 设置起终点；保留宿主 Ctrl+K、Ctrl+N、F5 等语义。首版不宣称真正逐帧解码步进。

## 资源目标

工具未使用时不启动 FFmpeg、不创建播放器。离开视频会话暂停播放，失活视图按宿主生命周期释放媒体资源。避免一次解码全片或为每帧建立缩略图，不预先复制源视频到数据目录。导出仅一条该工具重处理作业，FFmpeg 线程数受控，优先保证宿主交互。

2 GiB 现有作业内存预算与 4K/高帧率兼容先实测；首版优先验收 1080p SDR。包体、空闲/预览/导出内存、取消延迟和吞吐分别记录实测值，不在方案阶段编造 MB 或倍速承诺。
