# 视频裁剪初版技术方案

2026-11-11，VID-1。用户已明确授权按本方案实现。本地初版已完成，原设计保留，实际组件/接口及证据见本文末尾和task/checklist。

## 技术选择

保持 C++20 / Qt 6.8.3 Widgets。主界面增加可复用的 Qt Multimedia 视频预览/选段能力，业务工具使用独立 C++/QtCore 薄适配进程调用包内 ffprobe.exe / ffmpeg.exe。工具核心负责媒体分析、命令规划、进程控制和输出事务，不依赖宿主 Widgets。standalone CLI 和 integration adapter 调用同一核心。

使用 C++ 是为了复用本项目原生工具打包链并避免为薄调度层另带 Python，不意味着 C++ 编写的调度代码能显著加快 FFmpeg 编码。若未来独立视频工具已有 Python 核心，仍可用同一协议接入。

Qt 播放预览与 FFmpeg 导出使用各自锁定的依赖。Qt 的媒体插件/FFmpeg DLL 位于宿主运行时，工具 FFmpeg 可执行文件及其依赖位于工具包，不能假设可以直接混用 Qt 自带 DLL 或省略其部署。按需创建播放器可减少空闲工作，但增加链接模块并不保证所有相关 DLL 都能卸载或无常驻开销。

当前建议先采用宿主内 Qt 播放器，成本与既有框架相符。限制是播放器/媒体解码故障可能影响宿主，工具编码进程隔离不会隔离预览。若用户将所有媒体解码独立进程作为硬要求，需另做媒体服务、共享帧/音频同步、资源与协议设计，并重新评估范围，不能把两种架构混写成现成能力。

## 职责与边界

| 部分 | 职责 |
|---|---|
| 公共视频控件 | 播放、音量、时间轴、选段、时间输入、键盘与布局，按语义绑定源路径和字段 |
| 公共视图与校验 | 新版 UI 描述、事件动作绑定、类型化媒体元信息、媒体源/参数分别失效、草稿状态 |
| 调度与 WorkerHost | 现有作业生命周期、路径租约、进程树、取消、超时、内存和 CPU 预算 |
| video-clip/core | ffprobe 分析与归一化、能力判定、导出计划、FFmpeg 参数、输出验证与安全发布 |
| video-clip/integration | JSONL 协议输入输出、动作映射和结果组织，业务算法不放宿主 |
| 工具构建脚本 | 锁定 FFmpeg/ffprobe 来源与哈希、许可、私有运行文件、完整性清单 |

宿主不得出现按 tool_id == video-clip 分支的业务绘制或编码命令。可以有通用媒体控件、元信息绑定及声明式事件触发。源媒体路径属于显式输入，输出预览路径只能来自有效作业 artifacts，不能用任意包内 JSON 绕过路径和结果校验。

## 公共能力的兼容扩展

1. 引入 UI v2 媒体组件与有界事件/结果契约，保留 v1 渲染及校验路径。新包声明实际 min_host_version；旧宿主应给明确不兼容提示。具体控件名可用 video_editor，其内部组合播放器、范围时间轴及 TimecodeEdit，避免一套 JSON 为每帧更新状态。
2. 视频控件的 start_ms/end_ms 使用有界 64 位毫秒整数，后端换算到源 time_base 的有理时间。不能直接套当前 number 字段 1000000 最大值或 QString 浮点时间计算。
3. 媒体结果结构拟定 media，包含 source_revision、source_identity、duration_ms、width/height、display_rotation、视频/音轨索引、frame_rate 或 VFR 标识、codec/capabilities。可展示子集进入 UI，原始 ffprobe 输出只在工具内部，限制 JSON 大小/轨道数/探测时长。
4. 输入路径变化触发声明式 probe，沿用统一 Scheduler。其结果只在源 revision/identity 一致时接受。改变起止或压缩参数只使导出计划失效，不清除仍有效的媒体元信息。v1 现有 context 失效行为保持原语义，避免重命名预览失效回归。
5. 快速模式使用独立 prepare 动作分析起点附近关键帧，返回 request_fingerprint、实际可用区间和兼容性。用户接受调整后才启用 export；任何影响计划的参数变化使计划失效。无需全片扫描所有关键帧。
6. 参数分组、显隐、模式联动和自动分析事件按公共规范实现，不能通过工具代码直接控制宿主控件。需要的公共字段只有本轮需求涉及的部分，保留普通工具最短接入路径。
7. 当前总超时 3600 秒需调整。新版能力支持显式长作业总时限，拟定上限 86400 秒；旧 v1 包继续原有限制。探测、关键帧分析保持短超时；导出持续进度/存活与绝对期限区分，不能以“百分比暂未变化”直接判死。超时或系统资源限制给明确原因。字段与 Schema、运行时、SDK、文档和测试一起确定，不能只增大工具 manifest 数值。

## 关键动作契约

所有动作沿用当前 JSONL 协议 1，输入文件引用与参数不包含视频字节。能以有界类型化 result/context 扩展实现时无需改变协议消息封套；若实现前发现封套需要改变，先更新本方案和能力版本，不隐式破坏协议 1。

| 动作 | 输入 | 输出 | 取消与失败 |
|---|---|---|---|
| probe | 一个源文件、source_revision | 已校验 media 元信息、支持模式/原因 | 可取消，过期结果丢弃，无用户输出 |
| prepare | 源身份、区间、方式、质量/尺寸/音轨、输出目录/基础名 | 有界计划、参数指纹、快速模式调整区间、兼容性和被省略流提示 | 可取消，不写最终文件；参数改变失效 |
| export | 源文件、经校验的显式参数、最新计划/指纹 | artifacts 最终绝对路径，实际时长/大小、选定模式和警告 | 只成功提交后的文件计成功；重复点击运行时禁用，不自动重试 |

探测不读取整片到内存。计划不是信任凭证，export 必须独立验证参数、能力和源身份。相对时间以源可见时间零点定义，转换处理非零/负时间起点、编辑列表和音视频偏移。输出清零时间线并维持相对音画同步，不能分别清零每轨造成失步。

## 编码策略

精确模式初拟软件 H.264/AAC，libx264 可作为候选编码器，质量采用 CRF 类策略，按较高画质/均衡/较小文件映射经样片验证的参数。默认不强制更改帧率，不放大小尺寸素材，输出偶数尺寸并保持画面比例/像素宽高比语义。旋转在像素或正确元数据中一致表达，避免重复旋转。

快速模式只复制能力矩阵中可解码的选定流，源区间调整到已验证关键帧，输出容器由兼容性选择。禁止自动退化为重新编码，不支持时让用户切换方式。

首版不混用硬件与软件质量标尺，不自动开启硬件编码。使用包内 FFmpeg，启动参数通过参数数组，Windows 隐藏子进程，无 shell 拼接。FFmpeg -progress 的输出由适配器单独管道解析后节流为 SDK progress，不能原样混入宿主 JSONL stdout。stderr 持续排空并保留有界诊断，避免管道阻塞或日志爆量。

## 状态与文件事务

未导入 → 分析中 → 可编辑 → 准备导出 → 排队/处理中 → 输出校验 → 提交 → 成功。分析/准备/处理均有失败/取消分支。运行中冻结本次参数，视图分离收回不重新提交。切换会话暂停播放器，不取消用户已启动的后台导出。

输出目录默认源目录/ModynToolbox Exports。分配同目录独占临时路径，导出只写临时文件。临时扩展名与显式封装格式匹配。完成后关闭文件句柄、验证退出码和 ffprobe 结果，再预约最终目标并用禁止替换的提交方式发布。需要重排名称时重新预约，处理跨会话竞态与文件别名。源身份复验在分析/处理前后进行，文件句柄与实际提交检查沿用工程安全规则。

取消停止对应 FFmpeg，等待退出后清理自身临时文件；超时由 Job Object 终止。critical 只覆盖最终短文件提交，不覆盖整段编码，避免长时间不可取消。若提交后才收到取消，保留已完成输出并报告真实完成状态。崩溃残留启动扫描限本工具管理的暂存登记，不能按扩展名批量删除任意文件。

## 依赖与发布准备

开发前锁定实际 FFmpeg 版本、下载/构建来源、SHA256、构建参数、编码器和许可。包含 libx264 等组件会改变 FFmpeg 构建许可要求，需为实际分发构建提供对应许可/源代码材料，不能只写一个 LGPL 文案。单独进程也不能代替依赖许可核对。Qt Multimedia 部署单独验收，不能只把工具 exe 复制过去就宣称可用。

原规划阶段未增加二进制。本轮后续实现已生成本地验证包，正式发布仍单独控制。实现后本地打包验证与正式发布分开；正式发版需要用户当次明确要求。发布新宿主后，现有通用组件能表达的后续视频工具仅增加工具包；新增未支持 UI 类型仍需扩展宿主。
