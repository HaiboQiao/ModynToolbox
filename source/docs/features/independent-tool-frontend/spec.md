用户澄清这是项目初始目标：宿主提供箱子，工具拥有全部业务前端。早期将统一接入规范解释为统一组件树过度收窄。当前业务与依赖独立的实现继续有效，当前UI v1/v2/v3不能等同完整前端独立。UI-R6置顶修复已完成，保留其未提交工作。

## 行为需求

- F01 工具作者自行设计整个业务页面：结构、全部控件、布局、图表、预览、交互、响应式、动作与状态位置，无需宿主增加该业务组件。
- F02 宿主只管理导航、工具发现/版本、会话、容器、浮窗、调度与通用能力；中央不给工具插入固定业务参数栏/按钮栏/页脚。工具可选择使用主题建议而不被宿主QSS修改。
- F03 新工具能独立开发、调试、构建；遵守版本化前端接入和后端协议后，只放入完整工具包即可发现，不修改或重新构建宿主。
- F04 后端语言、运行时与依赖独立；UI生命周期和后台作业生命周期分离。UI重载、隐藏、迁移窗口不重复执行作业。
- F05 多会话数据隔离；内嵌/并排/独立窗显示同一会话的一份前端，迁移保留输入和未保存编辑状态。
- F06 懒加载、资源可观察、故障可局部恢复；安装100个工具不等于启动100套前端/后端。前端自有代码错误不能被表述为完全不会影响宿主。
- F07 安装/移除/升级保持目录语义，数据保留，旧会话固定版本；旧UI工具继续可用，逐个版本迁移。
- F08 完整离线便携包完整解压双击运行；前端资源随工具分发，不依赖CDN、开发服务器、用户npm/Python。运行时分发包含在方案中。

完整前端独立不等于任意现成桌面程序零适配嵌入。主路线约定Web前端承载契约，框架和业务设计自由；既有Qt/WPF等原生界面可保持外部独立窗口，但不冒充已满足完整内嵌能力。任意原生GUI嵌入不在第一轮承诺范围。

验收：两种框架、不同布局的新工具在宿主源码及EXE冻结后接入；双会话/双工具/崩溃与窗口迁移/离线分发均复验。具体步骤见checklist.md。
