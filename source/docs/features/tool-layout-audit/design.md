# UI-R6 布局审计与后续方向

2026-11-14。当前实际栈C++20/Qt 6.8.3 Widgets，宿主ToolPanel渲染声明式页面，Theme管理全局QSS；工具业务通过独立进程接入。没有切换框架或引入新依赖。

## 置顶故障与修复

app/ui/components/tool_panel.cpp的makeFields将参数容器垂直策略设为Maximum，限制为内容自然高度；AdaptiveRow没有指定交叉轴顶部对齐。左侧文件列表可以扩展，外层行增高时，右侧较小容器居中。内部normalGrid的AlignTop只控制容器内的网格，不能决定容器在外层的位置。

本次改为Preferred，使容器接收外层高度，内部已有尾部stretch吸收多余高度，字段自身自然高度不拉伸。宽屏左右置顶，窄屏继续上下排列。没有用固定坐标、负margin或固定高度掩盖问题。

## 当前控制边界

- tools/*/integration/ui.json：工具可选模块、行列嵌套、同排stretch权重（渲染器限1–4）、输入标题、说明、字段与动作内容。图片、重命名和文件校验目前实际采用同一files/fields并列结构，JSON采用文本输入/输出，视频采用video_editor。
- app/ui/components/tool_panel.cpp：node生成公共组件。actions/status节点返回空；构造函数将动作条和状态固定到工具页底部，ui.json中写的位置不会生效。files模块同时捆绑拖入、文件操作、表格与数量；fields模块捆绑参数标题和全部字段。
- app/ui/view_spec.cpp与shared/protocol/view-v*.schema.json：限制组件类型、树深度、总量与重复类型；当前参数最多12项，同种叶组件只能出现一次，不能声明多个参数组或多个文件列表。v3改善的是字段能力，不是自由页面框架。
- app/ui/theme/theme.cpp和docs/ui-design-system.md：字体、按钮、颜色、边框由宿主统一；工具没有独立QSS、HTML、QML或原生UI插件入口。

所以现状为“后端独立、前端在通用组件内组合”，不能描述为“任意独立前端直接嵌入”。共享故障域和接入边界沿用AGENTS。

## 后续建议（尚未实现）

建议保留公共控件规范，将工具页面编排权交给工具：版本化扩展区段/分组/网格/标签页，字段通过ID分组引用，动作和状态支持明确的页内/固定底部声明，模块比例、间距和滚动区域由工具配置。兼容旧UI v1/v2/v3的固定页脚，不能静默改变旧页面。新增属性必须同时落实Schema、实际解析、渲染、文档、状态与尺寸回归，禁止只写Schema就宣称可用。

普通工具沿用轻量声明式方式，接入已有能力无需修改宿主。若目标进一步变成工具可以自行绘制整个前端，需另外设计可选的自包含前端接入及状态桥接，评估运行时体积、内存、嵌入与浮窗生命周期；不能承诺当前支持。不能为了前端自由把任意原生插件加载进宿主而牺牲崩溃隔离。

设计原则：公共壳与基础控件保持一致，工具根据任务决定信息架构。文件校验可突出校验结果，图片工具可突出预览，重命名可突出前后对照；避免为了不同而更换基础按钮风格。该工具差异化改版本次未实施。

Qt高度策略与布局行为参考官方6.8文档（本环境无可调用Context7）：https://doc.qt.io/qt-6.8/qboxlayout.html 与 https://doc.qt.io/qt-6.8/qwidget.html#sizePolicy-prop。
