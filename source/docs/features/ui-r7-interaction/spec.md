# UIR-7 窗口与工作区交互优化

状态：本地实施与自动化验收完成；本地优化，不发布、不上传。

## 用户问题与原因
- 无框窗口需要可靠的八向系统缩放，同时不能让嵌入的原生浏览器覆盖缩放边缘。
- 旧生命周期切走立即保存并销毁页面，返回重新校验、启动页面。基线三次返回 JSON 约6380–6692ms，均丢失页面内临时身份标记（状态仍通过检查点恢复）。
- 工具页面1px边框叠加2px外轮廓及2px偏移，焦点显得过粗。
- 宿主24px和工具20px留白叠加，浪费工作区。
- 原生/Web数字和选择控件默认滚轮可能改值，滚动页面时容易误操作。

## 方案与验收
1. 通用ChromeWindow保留8逻辑像素功能缩放边缘，最大化归零；显示后恢复系统边框样式，边缘非客户区按下交由Windows系统缩放处理。主/独立窗口一致。验证显示后八向命中、样式、尺寸改变与布局，物理拖动/Snap/多DPI标为人工验收。
2. 最近两个闲置Web页面保温60秒，LRU超额或超时才检查点回收；活动/并排/独立/忙碌页面受保护。首次按需加载、完整性校验保留；检查点失败不丢页面。记录前后切换耗时、身份及状态、回收证据。
3. 五个工具自有CSS将文本/选择焦点改为1px边框变色，按钮保留细键盘焦点线。
4. 宿主工作区不再额外留白，工具自己保留12px内容内边距（窄屏10px），不强制任何工具布局。
5. 原生参数控件忽略滚轮；工具各自处理数字/范围/选择的滚轮，保持焦点和值，将滚动交给可滚动的祖先，鼠标点击及键盘修改继续有效。

## 保护范围
PB-01工具完整前端所有权：宿主不注入CSS/业务JS。PB-02后端/作业协议不改。PB-03检查点、分离、并排和忙碌保护保留。PB-04工具包1.2.2不覆盖，源码升1.2.3。PB-05/06不改数据、不自动重跑。PB-07缓存有数量/超时约束。PB-08后台私有数据验证，不控制用户鼠标、不发布。
