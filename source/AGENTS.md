# ModynToolbox 项目协作约定

## 先建立当前状态

本文件是本仓库的 Agent 工作入口。先读 README.md、docs/STATUS.md，再按任务读取 docs/spec.md、docs/plan.md、docs/task.md 和 docs/checklist.md。构建、数据和迁移规则见 docs/development.md，设计原因见 docs/decisions.md。

项目从独立规划基础建立，实时实现状态以 STATUS、任务和实际文件为准。接手时检查 Git 差异和验证证据，不能把规划中的路径/命令当作已经存在或已通过。后续实施依据当时用户授权与当前阶段推进。

## 架构与模块边界

- 宿主采用 C++20 / Qt 6 Widgets，跨语言后端独立进程接入。业务核心独立于宿主与 Qt UI。
- app/ 集中宿主代码及其测试。tools/<tool_id>/ 集中该工具的 core、standalone、integration、tests、资源及依赖声明。
- 工具业务核心只依赖自己的业务依赖。integration/adapter 负责公共协议，integration/ui.json 定义界面。共享 SDK 仅提供协议帮助。
- shared/ 保存接入规范及 SDK，宿主不加入按工具 ID 分支的业务处理。新型 UI 能力通过通用组件及规范版本扩展。
- 同工具多会话状态独立，分离/收回窗口不重新提交作业。各后端版本、环境、配置及数据独立。
- 工具后端不载入宿主进程，不写宿主数据库。IPC 有界，原始解码、复杂结果解析与业务处理离开 UI 线程。
- 当前接入可信本地工具。宿主 UI 是共享故障域，系统资源共享，不能把目录或进程隔离宣称为权限沙箱。

## 路径与数据

所有路径从项目根、工具包根或显式数据根解析。跟踪文件不硬编码用户盘符、用户名、Qt 安装路径或个人 Skill 路径。

开发数据默认 data/，工具数据集中 data/tools/<tool_id>/。生成物集中 .local/，各工具环境位于 .local/tools/<tool_id>/。业务源码不放入生成目录。工具原项目与安装副本分别管理。

修改前确认作用域与文件实际归属。任何递归清理/移动先解析绝对目标并确认属于授权目录。开发清理仅处理明确生成物。用户数据、待恢复 journal、原图和用户导出按各自策略保留。测试只操作自己的临时数据根和进程。

## 启动与验证

当前为完整 R2 实现，完成与待验范围见 STATUS 和 verification/R2-complete.md。统一使用 scripts/dev.ps1 的 doctor/configure/build/run/test/package 入口，参数与实际命令记录到开发指南。VS Code 和 CLI 使用同一 CMake Preset。不能为了让命令通过而跳过全部测试。

文件写入、取消、部分成功、恢复、升级与协议变更需要对应回归。编译、自动测试、真实 Windows GUI/DPI/多窗口、干净机器发布包各记录自己的证据，不能相互替代。

安装/构建依赖使用项目约定的环境，记录来源及锁定版本。本机 Qt/MSVC/CMake 路径放忽略的机器配置。新电脑重新检查环境，旧 .local/ 构建缓存按机器重建。

## 持续记录与交接

每个有意义的工作阶段结束时同步以下记录。

- docs/task.md 维护任务状态，docs/checklist.md 维护实际验收。
- docs/STATUS.md 保持简短，写当前阶段、最近通过的验证、缺口和明确下一步。
- docs/worklog.md 追加本阶段变更、实际命令/结果、相关文件与下一步，保留失败和局限。
- 改变架构、协议、目录或数据语义时更新 docs/decisions.md 与受影响规划。
- 验证输出放 docs/verification/ 下有意义的报告，原始大日志放 .local/，报告记录可复现入口与必要摘要。

代码和文档通过 Git 维护。提交只包含本任务相关变更，保留其他人的未提交工作。远程发布、推送和对外分享按会话授权执行。别的 Agent 缺少自动规则读取能力时使用 docs/handoff.md 的显式接手提示。

## 工作方式

沿用本项目设计和当前用户授权完成工作，按实际影响进行必要验证。完整实施授权内的常规步骤连续推进，避免反复请求同一授权。新增破坏性范围或关键需求分歧才请求必要澄清。

本项目说明自包含，不要求使用某个人电脑上的全局 Skill。库/框架/CLI 的版本相关用法优先查当前官方资料或可用 Context7，并在证据中说明来源。当前任务只读或规划时遵守对应范围，不把分析结论写成已实现事实。

## 非打扰验证

用户要求开发时能继续使用电脑。默认通过 windows-check 独立输出、Qt offscreen、测试日志与离屏截图验证，禁止例行测试抢占前台焦点、鼠标和键盘。无需桌面操作就能完成的工作使用脚本。原生标题栏、系统交互、DPI 和多屏等保留真实验收记录，需要实际桌面操作时先说明具体场景并安排时机。不要为编译而关闭用户正在使用的程序。

## 产品与界面约定

产品名称为 ModynToolbox，默认浅色雾紫主题。主题集中 app/ui/theme，公共控件集中 app/ui/components，主窗与浮窗复用 app/ui/window/ChromeWindow。Windows 外框代码集中 app/platform/windows，业务工具不处理窗口消息。新工具先使用自己 integration/ui.json 的版本化控件描述，宿主不按 tool_id 分支绘制业务页面。v1 规范已用于四个真实工具，新增工具优先使用已有公共组件。扩展公共组件时同步校验、渲染、Schema 和回归。

用户明确说“优化修改”的本项目小型需求，直接按范围完成实现与验证，不停留在方案说明。只有明确要求先分析/先给方案时交付对应阶段，并清楚说明实现状态。

## 发布入口

任何发布、打包、上传 GitHub、宿主/工具版本更新前先完整读取 docs/release-policy.md。正式上传使用固定源提交与标签，验证源码/便携/独立工具及公开下载，记录真实完成状态。仓库根负责 source/releases 路由，源码工程根为本目录。

## 发布触发边界

只有用户在本次任务中明确要求发布/发版，才执行正式版本发布。发布规则讨论、源码优化、修复与本地验证按当前任务授权处理。正式发布必须同时同步最新源码、说明、运行资产和发布回执到 GitHub，并完成远端及下载核验。单独源码同步按用户明确的同步授权执行。
